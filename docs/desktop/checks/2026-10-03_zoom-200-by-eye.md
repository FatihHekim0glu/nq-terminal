# Check: 200% zoom by eye, in small windows

Result: [ ] PASS   [ ] FAIL   Status: NOT RUN

## Purpose

Decision 1.2 of the register (`docs/desktop/owner_decisions_windows.md`, "Zoom at 200% in small windows") follows WCAG 2.2 AA success criteria 1.4.4 (Resize Text) and 1.4.10 (Reflow): at 200% zoom, in a 1366 by 768 window and in a 1024 by 640 window, every maximised panel keeps every control reachable. A control may move into an overflow menu or into a body that scrolls; it may not be clipped away or hidden behind another one.

The two desktop specs that used to be expected failures for this now pass ({{W6: result of the zoom specs of the desktop project}}). A test can show that a control exists and can be focused; it cannot show that a person can find it. This check is that look, by eye, on the installed release, with the keyboard and the mouse.

03 section 12 sets the context: the app's zoom runs from 50% to 300% in 25% steps through Ctrl+plus, Ctrl+minus and Ctrl+0, and the smallest window the app allows is 1,024 by 640 (decision O12). The dense two-dimensional panels rely on the reflow exception for data tables, so this check asks for reachability, not for a single column.

## Preconditions

- The release is installed and shows HOME with data.
- Know how to read the window size. The app shows no size, so read the window's client area, in pixels, with the read-only command below (run it in PowerShell while the app is open; it prints width by height).
- Resize the window by dragging its edge until the client area is within 20 pixels of the size you want. The app will not shrink below 1,024 by 640.

```powershell
Add-Type -Namespace NqChk -Name Win -MemberDefinition @'
[System.Runtime.InteropServices.DllImport("user32.dll")] public static extern bool GetClientRect(System.IntPtr h, out RECT r);
public struct RECT { public int Left, Top, Right, Bottom; }
'@
$h = (Get-Process -Name 'nq-lab-terminal' | Where-Object MainWindowHandle -ne 0 | Select-Object -First 1).MainWindowHandle
$r = New-Object NqChk.Win+RECT
[void][NqChk.Win]::GetClientRect($h, [ref]$r)
'{0} x {1}' -f ($r.Right - $r.Left), ($r.Bottom - $r.Top)
```

Run the whole block once in each PowerShell window. To read the size again in the same window, run only its last four lines.

3. [ ] For each panel in the table, open it, maximise it (the "Maximise panel" button in its header), and look at the whole panel. Tick the box when all four of these hold:
   - every control you can see in the same panel at 100% is still there, or is in an overflow menu ("More" or the panel's Options menu);
   - you can reach every control with the keyboard (Tab and Shift+Tab) and the focus ring is never hidden behind another part of the frame;
   - where a control moved into a scrolling body, the scroll bar is there and the control scrolls into view;
   - no text is cut off with no way to read the rest.

## Pass rule

PASS when every box in the table is ticked and steps 1 to 7 are done. A control that cannot be reached, a clipped control, or a focus ring hidden behind a frame is a FAIL for that cell. Write the panel, the size and the control in the note column, and file it as a defect (03 section 19 defect rule). A cell that fails only in the app and not at the same zoom in the browser terminal is an app defect first.
