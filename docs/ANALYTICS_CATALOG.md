# nq-lab terminal: analytics catalogue

Status: plan, 2026-09-26. Each row gives the ID, priority, formula, inputs, chart and QA reference. **[verified]** means confirmed on 2026-09-26 from code on disk, a numeric check or a fetched source; **[unverified]** means the QA gate of the phase that builds it must confirm it first.

The terminal never produces a new pass or fail. Verdicts come from the result files. Everything computed here is descriptive and says so.

## 0. Conventions that bind every metric

**C1. Two return bases. Every number names its basis.**
- **Basis A, "screen"** (registered hypotheses): `r_t = PnL_t / K`, arithmetic, K the fixed starting capital. Equity `K·(1 + cumsum r)`. Drawdown in units of K, peak to trough of `cumsum r` with a floor at 0. Matches `sizing_stats.max_drawdown` and the screen JSONs [verified, `src/nq_lab/sizing_stats.py`].
- **Basis B, "account"** (Nautilus runs): `r_t = E_t / E_{t-1} - 1` from `strategy_log.snapshots[].equity`, one snapshot per session (2,517 for `nt_dtsmom_v0_ts1`), compounding from `E_0 = K`.
- Runs without snapshots (`za_orb`, `overnight`): daily P&L from `trades` grouped by date, one row for every gated session with 0 on days with no trade, as `metrics.daily_pnl` does [verified, `src/nq_lab/metrics.py`]. Labelled "realised, no MTM".
- One-contract screen series (Basis A in USD): zero-filled over the window the screen served (`serve.start` to `serve.end`, else 2010-09-28 to the fence), never from the first to the last trade, so n and MinTRL (and SV3's common daily basis) are the screen's own (halloween_v0 Sharpe 0.8836 first to last, 0.8731 over the window). `eurodrift_v0` void nights count as 0, as the screen's unconditional book (`eurodrift_stats.daily_books`): 0.3923 over 2,835 nights, against 0.4340 on the 2,317 valid nights alone and C6.sharpe_uncond 0.3930 on the 2,825 sessions with both NQ closes (a set that needs prices).
- An account whose equity reaches zero or below cannot compound: its Basis B series is refused (the three lookahead probe runs) and served as 422 with the first such session.

**C2. Calendar and annualisation.** Trading sessions only, never calendar days. P = 252 for daily series, 12 for monthly books; never mixed. mean·P; sd(ddof=1)·√P; Sharpe = mean/sd(ddof=1)·√P; years = n/252 (as `volmanaged_v0.json`: 2686/252 = 10.6587) [verified]. Risk-free rate 0: futures P&L is already an excess return and the backtests earn no interest on cash.

**C3. Nautilus paths not used for displayed numbers.** `PortfolioAnalyzer.portfolio_returns()` and the tearsheet resample to calendar days, forward-fill and add a zero return on weekends, then annualise with √252 [verified, `analysis/analyzer.py:854-864`, `tearsheet.py:770-785`]. On a synthetic 5-year business-day series: correct Sharpe 0.2679, CAGR 3.01%, vol 15.64%; analyser path 0.2264, 2.14%, 13.21% [verified numerically]. Nautilus `Alpha` annualises geometrically (9.87% against 9.41% arithmetic on the same test) and has no Newey-West t [verified]. Nautilus pyo3 statistics are used only as a second implementation in tests, fed `{ts_ns: r}` on a session index.

**C4. Name collision.** In the screen JSONs `headline.*.dsr` is the **Sharpe difference** (managed minus buy-and-hold), not the Deflated Sharpe Ratio (`volmanaged_v0` 0tick: `dsr = -0.000281` = 0.99671 - 0.99699) [verified]. The UI labels it "Sharpe difference (m - BH)". "DSR" means only Bailey and López de Prado's statistic.

**C5. Prices only through the gate.** Views that need prices use `/api/bars` and `/api/market/*`, which go through `nq_lab.data.serve(caller="terminal")` with the in-memory year cache (`ARCHITECTURE.md` section 5). They end at 2021-12-31. 2022+ appears only from `results/sealed/` result columns, labelled "spent window, opened 2026-09-26, descriptive only".

**C6. Benchmark comes from the run's spec, never a default.** NQ sizing books: the same-exposure buy-and-hold columns `r_bh_k` in `*_daily.csv`. NQ intraday strategies: NQ buy-and-hold close to close. `dtsmom`: the long-only equal-risk book (`nt_dtsmom_v0_lo1`, or `r_lo_*` in `dtsmom_v0_monthly.csv`).

**C7. Tags.** Values read from a registered result carry `[PRE-REG]`. Values the terminal computes carry `[POST HOC]`. No p-value is shown on a slice the user picked interactively.

**C8. Implementation.** All formulas live as pure functions in `terminal/backend/nq_terminal/analytics/` (numpy and pandas, no hidden state, inputs as session-indexed Series); only `analytics/series.py`, which builds those Series, and `services/run_books.py`, which reads a run's rows (trades, fills, snapshots) and a book's raw closes through the gate for TA and EX, call the injected services. Where nq-lab already has the function (`sizing_stats.sharpe`, `max_drawdown`, `spanning_alpha`, `tails`, `lw_sharpe_test`, `memmel_z`; `metrics.daily_pnl`), the terminal imports it and tests that its own path agrees.

**SV3 construction (the common Basis A daily basis; written 2026-09-27, before any SV3 code).**
1. *Trials.* Every row of `results/registry.csv` with `registered` True, read at request time (21 on 2026-09-27, equal to `family_k`). N is that count. Unregistered checks (`za_v0_C3_gao_momentum`) and sealed confirmations are not trials. If any trial's series cannot be built the whole view is refused (503 naming the trial): V over a shorter list would understate the search.
2. *Series.* For each trial, the Basis A series exactly as `/api/analytics/hypothesis/{name}?cost=1` builds it (`analytics.series.hypothesis_series`, no bar service, so no gate read): one row per session of the window the screen served with 0 on sessions without a trade (one-contract trade screens summed per exit session, za_v0's gate-rejected sessions dropped), nights and one-contract daily series as recorded (eurodrift_v0 void nights worth 0), return-on-capital daily series as recorded, vt_har_v0 its P2 portfolio. Cost 1 tick per side for every trial, the one cost every screen records.
3. *Unit.* The Sharpe ratio is scale free, so USD per contract, basis points, fractions of K and vt_har_v0's sd units give comparable ratios; only the period has to be made common.
4. *Per-session Sharpe.* Daily series (P = 252: trades, nights, daily): `SR_d = mean / sd(ddof=1)` per session. Monthly books (P = 12: tsmom, dtsmom, carry, eomtsy, cskew, vrp_eq; no daily series exists in their result files): `SR_d = SR_m x sqrt(12/252)`, the per-session Sharpe with the same annualised value. This scaling assumes serially uncorrelated monthly returns and is stated beside the table.
5. *V and SR0.* `V` = sample variance (ddof = 1) of the N values `SR_d`. `SR0_d = sqrt(V) x ((1 - g) x PhiInv(1 - 1/N) + g x PhiInv(1 - 1/(N e)))`, g = 0.5772156649 (Euler-Mascheroni). Beside it (revision 2026-09-27, statistics review): the expected-maximum formula models the trials' Sharpe estimates as N(0, V) draws when no trial has skill, so a trial far from the rest for a known cause (step 9) inflates the empirical V and gives a meaningless bar. The view therefore also shows the null variance `V0 = mean over trials of 1/(n - 1) x P/252`: each trial's Mertens sampling variance of its per-period Sharpe `(1 - g3 SR + (g4 - 1)/4 SR^2)/(n - 1)` evaluated at SR = 0, where no trial has skill and the skewness and kurtosis terms vanish, moved to sessions (improvement run 2: the first revision used each trial's observed SR, which put mim_v0's cost drag back into V0). With its `SR0` and every trial's DSR under it (each PSR still on the trial's own moments, as in the paper). On 2026-09-27: V 0.02778 (SR0 5.09 annualised, every DSR below 1e-30) against V0 0.000368 (SR0 0.585 annualised; volmanaged_v0 DSR 0.903, tsmom_v0 0.920, eomtsy_v0 0.845, halloween_v0 0.825, overnight_v0 0.785). SR0 uses the paper's closed-form approximation of the expected maximum, which at N = 21 is 1.7% above the exact value (1.9221 against 1.8892), so each DSR errs low; the paper's formula is kept so the golden fixture (step 8) holds, and the note says so. DSR is defined for the selected (best) trial; the other rows are descriptive.
6. *DSR per trial.* `DSR_i = PSR(SR0)` (SV1's formula) on trial i's own series in its own period, under V and under V0: daily trials use `SR0_d`; monthly trials use `SR0_m = SR0_d x sqrt(252/12)`. n, skewness and raw kurtosis are the trial's own sample moments (bias=True, as SV1). A DSR below 1e-6 is printed as "< 0.000001", never as 1e-60.
7. *Output.* Per trial: name, kind, P, n, SR per period, `SR_d`, annualised Sharpe, skewness, kurtosis, SR0 in the trial's period and DSR under V, and the same two under V0; plus N, V, V0, `SR0_d` and SR0 annualised under each, the leave-one-out line (step 9) and a note on N: "N treats the registered rows as independent trials and counts no variant tried before registration: correlated trials make the effective N smaller, untracked variants make it larger". Tagged `[POST HOC]`, labelled "extra view only; never overrides a frozen pass bar", no pass or fail.
8. *Golden fixture.* The paper example (N = 100, V = 1/(2 x 250), T = 1250, skewness -3, raw kurtosis 10, SR = 2.5/sqrt(250)) gives SR0 = 0.1132 and DSR = 0.9004 to 4 decimals.
9. *Known feature and leave-one-out.* mim_v0's net Sharpe at 1 tick is -11.5 annualised (its turnover is 8.6 times a day), a deterministic cost drag rather than a sampling draw, far from every other trial, so it dominates V. The view names it and shows a leave-one-out line: V without the trial whose removal lowers it most, N kept at the full count (on 2026-09-27: without mim_v0, V 0.000793, 35 times smaller, SR0 0.859 annualised).
10. *Review status (recorded 2026-09-27, improvement run 3).* Reviewed. The statistics review of improvement run 2, made against the primary sources, covered the revised construction: V0 at SR = 0 (step 5), the leave-one-out line (step 9) and the note on N (step 7). It found no CRITICAL or HIGH issue in SV3 or SV3a and signed the construction off. The caveats that remain, each stated in the view or in a step above: (a) SR0 uses the paper's closed-form approximation of the expected maximum, 1.7% above the exact value at N = 21, so each DSR errs low (step 5); (b) N treats the registered rows as independent trials and counts no variant tried before registration, so the effective N may be smaller (correlated trials) or larger (untracked variants) (step 7); (c) a monthly book's per-session Sharpe assumes serially uncorrelated monthly returns (step 4); (d) under the empirical V the bar is dominated by mim_v0's deterministic cost drag, so V0 and the leave-one-out line are the readable bars, and V is kept for the record (steps 5 and 9); (e) DSR is defined for the selected (best) trial only, the other rows are descriptive (step 5); (f) the whole view is post hoc and never overrides a frozen pass bar (step 7).

## 14. QA protocol (applied at every phase gate)

1. **Three-way agreement.** For every P0 scalar: the terminal's `analytics/` package, the Nautilus pyo3 statistic where one exists (fed a session index), and the independent library in `terminal/qa`. Tolerance 1e-9 relative for closed forms (1e-12 for the anchors below). Bootstrap results exact under a fixed seed.
2. **Anchors to the project's own files** (exact):
   - `volmanaged_v0_daily.csv r_m_1` Sharpe 0.9914875364356387 (stored 0.9914875364356394), `r_bh_1` 0.9946882195853758;
   - `dtsmom_v0_monthly.csv r_ts_1` Sharpe (√12) 0.25493487321272734, 120 months;
   - `volmanaged_v0.json` `years` 10.6587 and block alphas and t values;
   - ledger `t_net_r` equals `summary.t_net_r` for every ledgered run;
   - registry Bonferroni, Holm and BH columns;
   - equity from snapshots ends at `balance_check.final_usd`; realised curves end at `pnl_total`.
