# nq-lab terminal: analytics catalogue

Status: plan, 2026-09-26. Each row gives the ID, priority, formula, inputs, chart and QA reference. **[verified]** means confirmed on 2026-09-26 from code on disk, a numeric check or a fetched source; **[unverified]** means the QA gate of the phase that builds it must confirm it first.

The terminal never produces a new pass or fail. Verdicts come from the result files. Everything computed here is descriptive and says so.

## 0. Conventions that bind every metric

**C1. Two return bases. Every number names its basis.**
- **Basis A, "screen"** (registered hypotheses): `r_t = PnL_t / K`, arithmetic, K the fixed starting capital. Equity `K·(1 + cumsum r)`. Drawdown in units of K, peak to trough of `cumsum r` with a floor at 0. Matches `sizing_stats.max_drawdown` and the screen JSONs [verified, `src/nq_lab/sizing_stats.py`].
- **Basis B, "account"** (Nautilus runs): `r_t = E_t / E_{t-1} - 1` from `strategy_log.snapshots[].equity`, one snapshot per session (2,517 for `nt_dtsmom_v0_ts1`), compounding from `E_0 = K`.
- Runs without snapshots (`za_orb`, `overnight`): daily P&L from `trades` grouped by date, one row for every gated session with 0 on days with no trade, as `metrics.daily_pnl` does [verified, `src/nq_lab/metrics.py`]. Labelled "realised, no MTM".
- One-contract screen series (Basis A in USD): zero-filled over the window the screen served (`serve.start` to `serve.end`, else 2010-09-28 to the fence), never from the first to the last trade, so n and MinTRL (and SV3's common daily basis) are the screen's own (halloween_v0 Sharpe 0.8836 first to last, 0.8731 over the window). `eurodrift_v0` void nights count as 0, as the screen's unconditional book (`eurodrift_stats.daily_books`): 0.3923 over 2,835 nights, against 0.4340 on the 2,317 valid nights alone and C6.sharpe_uncond 0.3930 on the 2,825 sessions with both NQ closes (a set that needs prices).
- An account whose equity reaches zero or below cannot compound: its Basis B series is refused (the three lookahead probe runs) and served as 422 with the first such session.

**C2. Calendar and annualisation.** Trading sessions only, never calendar days. P = 252 for daily series, 12 for monthly books; never mixed. mean·P; sd(ddof=1)·√P; Sharpe = mean/sd(ddof=1)·√P; years = n/252 (as `volmanaged_v0.json`: 2686/252 = 10.6587) [verified]. Risk-free rate 0: futures P&L is already an excess return and the backtests earn no interest on cash.

**C3. Nautilus paths not used for displayed numbers.** `PortfolioAnalyzer.portfolio_returns()` and the tearsheet resample to calendar days, forward-fill and add a zero return on weekends, then annualise with √252 [verified, `analysis/analyzer.py:854-864`, `tearsheet.py:770-785`]. On a synthetic 5-year business-day series: correct Sharpe 0.2679, CAGR 3.01%, vol 15.64%; analyser path 0.2264, 2.14%, 13.21% [verified numerically]. Nautilus `Alpha` annualises geometrically (9.87% against 9.41% arithmetic on the same test) and has no Newey-West t [verified]. Nautilus pyo3 statistics are used only as a second implementation in tests, fed `{ts_ns: r}` on a session index.

**C4. Name collision.** In the screen JSONs `headline.*.dsr` is the **Sharpe difference** (managed minus buy-and-hold), not the Deflated Sharpe Ratio (`volmanaged_v0` 0tick: `dsr = -0.000281` = 0.99671 - 0.99699) [verified]. The UI labels it "Sharpe difference (m - BH)". "DSR" means only Bailey and López de Prado's statistic.

**C5. Prices only through the gate.** Views that need prices use `/api/bars` and `/api/market/*`, which go through `nq_lab.data.serve(caller="terminal")` with the in-memory year cache (`ARCHITECTURE.md` section 5). They end at 2021-12-31. 2022+ appears only from `results/sealed/` result columns, labelled "spent window, opened 2026-09-26, descriptive only".

**C6. Benchmark comes from the run's spec, never a default.** NQ sizing books: the same-exposure buy-and-hold columns `r_bh_k` in `*_daily.csv`. NQ intraday strategies: NQ buy-and-hold close to close. `dtsmom`: the long-only equal-risk book (`nt_dtsmom_v0_lo1`, or `r_lo_*` in `dtsmom_v0_monthly.csv`).

**C7. Tags.** Values read from a registered result carry `[PRE-REG]`. Values the terminal computes carry `[POST HOC]`. No p-value is shown on a slice the user picked interactively.

**C8. Implementation.** All formulas live as pure functions in `terminal/backend/nq_terminal/analytics/` (numpy and pandas, no hidden state, inputs as session-indexed Series); only `analytics/series.py`, which builds those Series, and `services/run_books.py`, which reads a run's rows (trades, fills, snapshots) and a book's raw closes through the gate for TA and EX, call the injected services. Where nq-lab already has the function (`sizing_stats.sharpe`, `max_drawdown`, `spanning_alpha`, `tails`, `lw_sharpe_test`, `memmel_z`; `metrics.daily_pnl`), the terminal imports it and tests that its own path agrees.

**SV3 construction (the common Basis A daily basis; written 2026-09-27, before any SV3 code).**
1. *Trials.* Every row of `results/registry.csv` with `registered` True, read at request time (21 on 2026-09-27, equal to `family_k`). N is that count. Unregistered checks (`za_v0_C3_gao_momentum`) and sealed confirmations are not trials. If any trial's series cannot be built the whole view is refused (503 naming the trial): V over a shorter list would understate the search.
2. *Series.* For each trial, the Basis A series exactly as `/api/analytics/hypothesis/{name}?cost=1` builds it (`analytics.series.hypothesis_series`, no bar service, so no gate read): one row per session of the window the screen served with 0 on sessions without a trade (one-contract trade screens summed per exit session, za_v0's gate-rejected sessions dropped), nights and one-contract daily series as recorded (eurodrift_v0 void nights worth 0), return-on-capital daily series as recorded, vt_har_v0 its P2 portfolio. Cost 1 tick per side for every trial, the one cost every screen records.
3. *Unit.* The Sharpe ratio is scale free, so USD per contract, basis points, fractions of K and vt_har_v0's sd units give comparable ratios; only the period has to be made common.
4. *Per-session Sharpe.* Daily series (P = 252: trades, nights, daily): `SR_d = mean / sd(ddof=1)` per session. Monthly books (P = 12: tsmom, dtsmom, carry, eomtsy, cskew, vrp_eq; no daily series exists in their result files): `SR_d = SR_m x sqrt(12/252)`, the per-session Sharpe with the same annualised value. This scaling assumes serially uncorrelated monthly returns and is stated beside the table.
5. *V and SR0.* `V` = sample variance (ddof = 1) of the N values `SR_d`. `SR0_d = sqrt(V) x ((1 - g) x PhiInv(1 - 1/N) + g x PhiInv(1 - 1/(N e)))`, g = 0.5772156649 (Euler-Mascheroni). Beside it (revision 2026-09-27, statistics review): the expected-maximum formula models the trials' Sharpe estimates as N(0, V) draws when no trial has skill, so a trial far from the rest for a known cause (step 9) inflates the empirical V and gives a meaningless bar. The view therefore also shows the null variance `V0 = mean over trials of 1/(n - 1) x P/252`: each trial's Mertens sampling variance of its per-period Sharpe `(1 - g3 SR + (g4 - 1)/4 SR^2)/(n - 1)` evaluated at SR = 0, where no trial has skill and the skewness and kurtosis terms vanish, moved to sessions (improvement run 2: the first revision used each trial's observed SR, which put mim_v0's cost drag back into V0). With its `SR0` and every trial's DSR under it (each PSR still on the trial's own moments, as in the paper). On 2026-09-27: V 0.02778 (SR0 5.09 annualised, every DSR below 1e-30) against V0 0.000368 (SR0 0.585 annualised; volmanaged_v0 DSR 0.903, tsmom_v0 0.920, eomtsy_v0 0.845, halloween_v0 0.825, overnight_v0 0.785). SR0 uses the paper's closed-form approximation of the expected maximum, which at N = 21 is 1.7% above the exact value (1.9221 against 1.8892), so each DSR errs low; the paper's formula is kept so the golden fixture (step 8) holds, and the note says so. DSR is defined for the selected (best) trial; the other rows are descriptive.
6. *DSR per trial.* `DSR_i = PSR(SR0)` (SV1's formula) on trial i's own series in its own period, under V and under V0: daily trials use `SR0_d`; monthly trials use `SR0_m = SR0_d x sqrt(252/12)`. n, skewness and raw kurtosis are the trial's own sample moments (bias=True, as SV1). A DSR below 1e-6 is printed as "< 0.000001", never as 1e-60.
7. *Output.* Per trial: name, kind, P, n, SR per period, `SR_d`, annualised Sharpe, skewness, kurtosis, SR0 in the trial's period and DSR under V, and the same two under V0; plus N, V, V0, `SR0_d` and SR0 annualised under each, the leave-one-out line (step 9) and a note on N: "N treats the registered rows as independent trials and counts no variant tried before registration: correlated trials make the effective N smaller, untracked variants make it larger". Tagged `[POST HOC]`, labelled "extra view only; never overrides a frozen pass bar", no pass or fail.
8. *Golden fixture.* The paper example (N = 100, V = 1/(2 x 250), T = 1250, skewness -3, raw kurtosis 10, SR = 2.5/sqrt(250)) gives SR0 = 0.1132 and DSR = 0.9004 to 4 decimals.
9. *Known feature and leave-one-out.* mim_v0's net Sharpe at 1 tick is -11.5 annualised (its turnover is 8.6 times a day), a deterministic cost drag rather than a sampling draw, far from every other trial, so it dominates V. The view names it and shows a leave-one-out line: V without the trial whose removal lowers it most, N kept at the full count (on 2026-09-27: without mim_v0, V 0.000793, 35 times smaller, SR0 0.859 annualised).
10. *Review status (recorded 2026-09-27, improvement run 3).* Reviewed. The statistics review of improvement run 2, made against the primary sources, covered the revised construction: V0 at SR = 0 (step 5), the leave-one-out line (step 9) and the note on N (step 7). It found no CRITICAL or HIGH issue in SV3 or SV3a and signed the construction off. The caveats that remain, each stated in the view or in a step above: (a) SR0 uses the paper's closed-form approximation of the expected maximum, 1.7% above the exact value at N = 21, so each DSR errs low (step 5); (b) N treats the registered rows as independent trials and counts no variant tried before registration, so the effective N may be smaller (correlated trials) or larger (untracked variants) (step 7); (c) a monthly book's per-session Sharpe assumes serially uncorrelated monthly returns (step 4); (d) under the empirical V the bar is dominated by mim_v0's deterministic cost drag, so V0 and the leave-one-out line are the readable bars, and V is kept for the record (steps 5 and 9); (e) DSR is defined for the selected (best) trial only, the other rows are descriptive (step 5); (f) the whole view is post hoc and never overrides a frozen pass bar (step 7).

**SV3b construction (the effective number of trials; recorded 2026-09-29 with its implementation; the constants in step 7 were fixed in the plan before any code and chosen on no result).** SV3 counts the registered rows as independent trials (SV3a step 7 says correlated trials make the effective N smaller). SV3b measures that from the trials' own returns and shows what a smaller N would do to the bar. It is an extra view beside the served N = 21 row, never a replacement for it.
1. *Trials.* Daily trials = the `DeflatedView` rows with P = 252 (trades, nights and daily rows: 15 on 2026-09-27). Their series are read one GET each, `GET /api/analytics/hypothesis/{name}?cost=1` (TRIAL_COST = 1 tick per side, the cost SV3 reads at), on the tear sheet's own query key so the two share the cache, and only once 87) Effective trials is selected. Monthly books (P = 12, 6 on 2026-09-27) have no daily series, so they are counted as independent trials: N_total = N_eff(daily) + the monthly count (SV3a step 4's serial-independence assumption, restated).
2. *Refusals (integrity).* Nothing is drawn unless the browser first reproduces what SV3 served, checked in this order and stopped at the first failure: (a) the view names no daily trial; (b) any daily trial's series could not be read (every trial is needed, as in SV3a step 1; the view names how many and the first reason); (c) `expectedMaxSr0(V0, N, gamma)` equals the served `sr0_null_session` to ANCHOR_TOLERANCE_SR0 = 1e-12 and every row whose served `dsr_null` is at least 1e-300 is reproduced by `probabilisticSharpe(sr, SR0 x sqrt(252/P), n, skew, kurt)` to ANCHOR_TOLERANCE_DSR = 1e-9; (d) for each daily trial in the served order, the count of finite returns equals the served `n` (basis) and the per-session Sharpe (SV3a step 4: mean over sample sd, ddof 1) equals the served `sr_session` to SERIES_TOLERANCE = 1e-9 relative (sharpe); (e) fewer than MIN_COMMON_SESSIONS = 252 sessions on which every daily trial has a return; (f) a trial that does not vary on the common window. A refusal is a status line naming what failed, never an alert, and draws no matrix.
3. *Correlation.* Pearson (never Spearman) of the daily trials on the common window: the sorted dates on which every daily trial has a finite return, at least 252. Each column is centred with one correction pass; the diagonal is exactly 1 and the matrix exactly symmetric.
4. *Eigenvalue estimators.* Eigenvalues of the correlation matrix by the cyclic Jacobi method. Participation ratio `(sum l)^2 / sum l^2` and the Li and Ji (2005) count `sum over l of (|l| >= 1 ? 1 : 0) + (|l| - floor |l|)`, which jumps by one at every integer eigenvalue of 2 or more, so it is read as a count with that edge.
5. *Clusters.* Average linkage (UPGMA, never single or complete) on the distance 1 - rho, cut at CLUSTER_CUT = 0.5 (`scipy.cluster.hierarchy.fcluster`, criterion `distance`); N is the number of clusters. The heatmap lists the trials cluster by cluster, the largest cluster first, so a cluster is a block on the diagonal.
6. *SR0 and DSR under each N.* SR0 = the SV3a step 5 closed form under the served V0 and the served gamma at N_total of each estimator (V0 is not recomputed for a different N); annualised as session x sqrt(252). Every registered row's DSR is `probabilisticSharpe` on its own moments in its own period under each N_total (a monthly book uses SR0 x sqrt(252/12)), beside the served DSR V0 at N = 21. Three estimators are shown and none is chosen: they can disagree, and the view gives no verdict.
7. *Pre-registered constants.* CLUSTER_CUT 0.5 on 1 - rho, average linkage; TRIAL_COST 1 tick per side; a daily trial is a row with P = 252; MIN_COMMON_SESSIONS 252; SERIES_TOLERANCE 1e-9 relative; ANCHOR_TOLERANCE_SR0 1e-12 and ANCHOR_TOLERANCE_DSR 1e-9; monthly books counted as independent (N_total = N_eff(daily) + monthly count). None is tuned to a result.
8. *Caveats, each stated in the view or here.* (a) A smaller N lowers SR0 and raises every DSR, so this view errs towards flattering a trial: the served N = 21 row stays the frozen reading and this is read beside it. (b) The correlation is of returns on the common window, not of how the trials were chosen; untracked variants tried before registration make the true N larger (SV3a step 7). (c) Counting the monthly books as independent overstates N_total if they correlate with the daily trials; no daily series exists to test it. (d) The eigenvalue estimators and the cluster count are descriptions of one sample correlation matrix, with no interval. (e) Post hoc and an extra view only: it never overrides a frozen pass bar and gives no verdict.
9. *Status of the checks.* The arithmetic is pinned to numpy and scipy by `qa/golden/p12_neff.json` and the served SV3 view at N = 21 is reproduced from the captured `DEFLATED_REAL` (see the SV3b row). The offline demo captures one daily series (volmanaged_v0), so it shows the refusal "Not computed: 14 of 15 daily trials series could not be read"; the gallery entry EffectiveN draws the full view from a seeded synthetic panel, labelled not research data. Whether a live backend's served daily series reproduce SV3's `n` and `sr_session` (the basis and sharpe refusals) is not yet run against the real files: until it is, the view may correctly refuse there.

**SV8 construction (the family test; recorded 2026-10-01 with its implementation, before the route serves any real family).**
1. *Family.* Every row of `results/registry.csv` with `registered` True whose series source (`constants.SERIES_SOURCES`) is one NQ contract in USD per session (`series.ONE_NQ` in its unit) and daily (P = 252): 11 rows on 2026-09-27 (za_v0, tom_v0, preholiday_v0, prefomc_v0, overnight_v0, macroday_v0, halloween_v0, rebal_v0, mac5rev_v0, fomccycle_v0, fomctone_v0). The family is fixed by this rule, never picked on screen, so its p-values are family-wise over pre-registered hypotheses. Every other registered row is listed with its reason (a monthly book has no daily series; a series in return on capital, basis points or sd units has a differential against one NQ contract in another unit, and the statistic compares raw mean differentials). Unregistered checks and sealed confirmations are not members. One member that cannot be built refuses the whole view (503 naming it).
2. *Series and common index.* Each member's Basis A series at 1 tick per side exactly as the tear sheet and SV3 build it. The common index is the sessions every member has, less the sessions where the benchmark has no close to close change (counted as `bench_missing`); each member's own sessions outside it are counted, with those that carried P&L.
3. *Benchmarks, two rows (amended 2026-10-01, before any real family was served).* The primary row is **cash**, `r_0 = 0`, so `d_i = r_i`: the null is that no member has a positive mean per session, the null the registrations (p and control p), SV3, MT power and the deflated Sharpe ratio all use, and its correlation of the differentials is MT 87's correlation of the returns. The second row, nested in the primary view as `buy_and_hold` and labelled as a different null, is NQ buy and hold on one contract, close to close in USD per session, no costs, the 1d vendor series through the gate. It is the much harder null: one contract held earned about +$96 a session from 2010 to 2021, so a member that is in the market 5% of sessions and earns twice buy and hold on its days has a mean r of about $9.7 and a mean d of about -$87, falls out of the consistent set and leaves the p-values near 1 almost regardless of member quality. It is read beside the cash row, never instead of it. In-sample only, nothing after 2021-12-31; cash reads no price.
4. *Losses.* `L_i = -r_i`; the benchmark's loss is `L_0 = -r_0`, with `r_0 = 0` for cash and `r_0 = r_bh` for buy and hold. Differential `d_i = L_0 - L_i = r_i - r_0` (`r_i` against cash, `r_i - r_bh` against buy and hold), so a positive mean says member i beats the benchmark. The null is that no member does (every E[d_i] <= 0). The cash row uses every session the members share (`bench_missing` 0); the buy and hold row drops the sessions where the benchmark has no close change.
5. *Statistic, as arch 8.0.0 computes it.* `max_i mean(d_i)`, not studentised (White's form; arch's `studentize` flag only names the method). The kernel variances `var_i = sum(e^2)/t + 2 sum_{k=1}^{t-1} kappa_k sum(e_s e_{s+k})/t` (`kappa_k = (1 - k/t)(1 - p)^k + (k/t)(1 - p)^(t-k)`, `p = 1/block`) enter only the consistent recentring. Recentring: upper recentres every member at its mean (White's Reality Check, the `upper` p-value), lower recentres only members at or above the benchmark (`max(mean, 0)`), consistent recentres a member only when `mean >= -sqrt(var/t x 2 ln ln t)`. The p-value is the share of replications whose maximum over the members is strictly above the observed maximum; critical values are numpy's linear percentile at 100 (1 - size).
6. *StepM (Romano and Wolf 2005, as arch runs it).* Reject every member whose mean exceeds the consistent critical value at size 0.05; while something was rejected and fewer members than the family were rejected, drop the rejected members, recompute the critical value over the rest from the same replications and reject again. The view names the members, the step that rejected each, and the steps taken.
7. *Bootstrap.* Stationary bootstrap of the rows of d, 10,000 replications, seed 20260927, drawing arch's random numbers in arch's order (`bootstrap.stationary_indices`). Block length: Politis and White (2004) with the Patton, Politis and White (2009) correction, arch's variant (`bootstrap.optimal_block_length`, the code SV5 uses) for each column of d; the family's block is their mean floored at 1 (`MIN_BLOCK`), the one number the draws and the variance kernel both use. The floor is needed because Politis-White often comes out below 1 for near-iid differentials (37% of 200 iid seeds at t 2,500, minimum 0.089): `p = 1/block` would exceed 1, `(1 - p)^k` alternates in sign and grows, the kernel variance is understated (0.26 against 1.005 at block 0.5; the consistent set then shrinks and the consistent p-value is too liberal) and below about 0.33 the power overflows. At block 1, `p = 1` and the kernel is the sample variance. arch 8.0.0's `_compute_variance` has the same code, so the crosscheck passes the same floored block to arch.
8. *Effective number of members (MT 88, added 2026-10-01).* The backend serves the Pearson correlation of the members' loss differentials on the common index (`SpaView.correlation`, k by k in the order of `members`; null for a member that does not vary). It is the correlation of d_i, the series the bootstrap resamples, so it is the dependence the maximum statistic runs over. It is not the number of independent hypotheses: every d_i holds -r_bh, so against buy and hold a low-exposure member (a sparse calendar book, d_i about -r_bh on most sessions) has its correlation pulled towards 1, while the members' returns are not (the returns' correlation is MT 87's, to be read beside this one, not replaced by it). Against a cash benchmark the two are equal. The browser reads it with SV3b's estimators: eigenvalue participation `(sum l)^2 / sum l^2`, Li and Ji (2005), and UPGMA clusters at 1 - rho = 0.5. It refuses (a status line, nothing drawn) for one member, for a member with no correlation, and for a matrix that is not a k by k correlation matrix. It is a reading beside the p-values: it does not adjust them.
9. *Caveats.* arch 8.0.0's statistic is the maximum raw mean differential, so it favours members with a large scale or spread in USD (the one unit rule in step 1 fixes the unit only, not the spread, which still differs by exposure: a strong low-variance member can be hidden by a noisy one; Hansen's studentised statistic would not, and arch cannot compute it); the Reality Check is conservative when poor members are in the family, which the lower and consistent p-values address; the family is the 11 rows of 2026-09-27 and grows only when a new registered row meets step 1; in-sample only, post hoc, never overrides a frozen pass bar.
